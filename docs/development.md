# 开发与验收

## 阶段

1. 当前底座：主机状态机测试、模拟器、ESP32-S3 编译。无硬件、无车辆资料即可进行。
2. 硬件到货：记录 SKU/原理图/供电，建立 GPIO 表；台架测试雷达去抖、相机/补光断电、故障与急停，不连接车辆。
3. 视觉：选模型及商业使用许可，现场录入；固定数据集测试本人、陌生人、照片/视频、昼夜/贴膜；未达到预定指标只保留手动模式。
4. 通信：实现可信识别消息及反重放；拔线、重启、伪造、超时全部拒绝；对输出驱动故障制定反馈机制。
5. BLE：审查并锁定上游版本与许可，实现 BLE/存储适配；只接 Unlock；现场 Driver 配对，单次人工触发验证。
6. 封闭场地端到端：靠近 → 识别 → 单次解锁；确认仍需独立钥匙驾驶；测试断连、失电、急停、错误身份、录屏欺骗、冷却、设备留车内行为。
7. 长时验证：车辆休眠、续航影响、热与欠压保护、连续误触发、日志隐私。通过前禁止无人看管自动使用。

## 首版测试覆盖

主机测试覆盖默认禁用、正常识别窗口、重复靠近、不匹配会话、缺活体拒绝、到期边界、陈旧结果、冷却、DryRun、急停锁存/复位、手动关闭。此测试不证明真实生物识别、抗攻击、BLE 或 GPIO 正常。

CI 的 host 和 firmware 分开执行，固件编译成功也不等于硬件验证。首版不含真实人脸模型或 BLE 依赖，避免把空适配器报告为实车能力。
